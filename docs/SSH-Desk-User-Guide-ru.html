Глава 01
Знакомство с SSH Desk

SSH Desk — это настоящий устанавливаемый продукт для управления всеми вашими SSH-серверами на Ubuntu, а не демонстрационный образец. Три модуля — десктопный GUI, командная строка и общее ядро — работают ровно с одной базой данных и одним хранилищем секретов: зарегистрируйте сервер в GUI и в тот же момент подключайтесь к нему из любого терминала командой sss prod, даже если GUI вообще не запущен.

Движком подключения является OpenSSH самой системы; протокол SSH не реализован заново, поэтому поведение подключения в точности как у Ubuntu. Встроенный терминал — настоящий PTY: цвета, стрелки, Ctrl+C, vim и nano работают корректно. Пароли хранятся только в GNOME Keyring и никогда не попадают в базу данных, логи, аргументы команд или переменные окружения.

GUI — интерфейс

PySide6 с тёмной/светлой темой, 7 языков интерфейса (полный RTL для персидского и арабского), многовкладочный терминал и файловый менеджер.

CLI — командная строка

Команда sss работает без GUI; имя команды настраивается; есть автодополнение bash/zsh.

Core — общее ядро

SQLite + SQLAlchemy с миграциями, сервис Keyring, конструктор ssh-команд и политика Host Key.

Глава 02
Установка и настройка

› Предварительные требования

# Ubuntu 22.04 / 24.04+ sudo apt update sudo apt install -y openssh-client gnome-keyring libsecret-1-0 \ python3 python3-venv python3-pip

› Вариант A — установка на уровне пользователя (рекомендуется, без sudo)

git clone https://github.com/hmplus28/SSH-Desk.git cd SSH-Desk bash scripts/install.sh

Скрипт проверит Python и OpenSSH, создаст виртуальное окружение в ~/.local/share/ssh-desk/venv, установит пакет со всеми зависимостями и создаст в ~/.local/bin ярлыки ssh-desk (GUI), ssh-desk-cli, ssh-desk-askpass и sss; также установятся автодополнение bash и значок приложения.

› Вариант B — системный DEB-пакет

bash scripts/package_deb.sh sudo apt install ./dist/ssh-desk_1.0.0_amd64.deb

DEB устанавливает автономный комплект PyInstaller в /opt/ssh-desk и регистрирует пункт меню и системный значок. Обновление выполняется установкой нового пакета поверх; ваши данные и секреты остаются нетронутыми.

› Слабый или прерывающийся интернет: зеркала и офлайн-установка

Если ваша сеть нестабильна или PyPI труднодоступен — не переживайте: каждый вызов pip в скриптах установки автоматически перебирает цепочку зеркал — недоступное зеркало пропускается без вашего участия и пробуется следующее. Порядок по умолчанию: официальный PyPI → ArvanCloud (Иран) → TUNA → Aliyun → Tencent.

# force a specific working mirror bash scripts/install.sh --mirror-name ir # ArvanCloud (Iran) bash scripts/install.sh --mirror-name tuna # TUNA (China) # 1) download everything once (on any working network) bash scripts/download_wheels.sh --mirror-name ir # 2) install later with NO network at all bash scripts/install.sh --offline

В режиме --offline pip запрещены любые сетевые соединения, установка идёт только из папки vendor/wheels — поэтому обрыв интернета посреди установки больше не оставит её недоделанной. Та же цепочка зеркал используется в scripts/build.sh, так что сборка DEB тоже защищена от сбоев сети.

› Где находятся важные файлы?

Глава 03
Быстрый старт: первый сервер

Шаг 1 — запуск: выполните ssh-desk, чтобы открыть GUI; или оставайтесь целиком в терминале и используйте sss add.

Шаг 2 — добавление сервера: на странице Servers нажмите «Add server». Введите имя, псевдоним (уникальный — именно им вы подключаетесь), хост, порт, имя пользователя и путь по умолчанию. Если выбрана аутентификация паролем, секрет сразу сохраняется в GNOME Keyring — не в базе данных. Перед сохранением кнопка Test выполняет реальное подключение, чтобы вы убедились, что всё верно.

# the same thing from the terminal (interactive wizard) sss add sss add --alias prod --host 192.168.1.1 --port 22 --user root \ --auth password --path /var/www

Шаг 3 — подключение: в любом терминале наберите sss prod, чтобы открыть интерактивную оболочку на пути по умолчанию. В GUI достаточно двойного клика по серверу, чтобы открыть настоящую вкладку терминала.

Первое подключение: показывается отпечаток ключа хоста; сверьте его с администратором сервера и примите один раз. Если ключ хоста позже изменится, подключение мгновенно отклоняется, и выводится подсказка о проверке возможной MITM-атаки.
Глава 04
Подключение и управление путями

У каждого сервера может быть путь по умолчанию и любое количество именованных сохранённых путей; например, определите один раз website → /var/www/html и nginx → /etc/nginx для боевого сервера и всегда прыгайте в нужную папку одним словом:

sss prod # shell at the server's default path sss prod nginx # shell at the saved path named "nginx" sss prod /var/www # shell at any absolute path sss prod --exec "uptime" # run one command, no shell sss prod --user ubuntu --port 2222 # per-run override (NOT saved) sss prod --dry-run # print the exact ssh command

Если запрошенного пути нет на сервере, сообщение об ошибке понятное и внятное — а не загадочный обрыв. Пути передаются с безопасным экранированием (shlex), поэтому пробелы и специальные символы в именах папок не создают проблем. Опции --user и --port действуют только для этого запуска и никогда не сохраняются.

› Коды выхода CLI

КодЗначение
0Операция успешна
1Ошибка выполнения (подключение, сеть, Keyring и т. д.)
2Недопустимый ввод или неверное использование команды
130Прервано по Ctrl+C

Эти коды делают sss предсказуемым в ваших скриптах и автоматизации; например, в CI или cron можно проверять успешность подключения.

Глава 05
Полный справочник CLI sss

Имя команды sss — лишь пример; переименуйте её командой sss config cli-name cnc во что угодно (cnc, sshgo, …) — изменение действует на уровне всей системы (новый ярлык в ~/.local/bin). Любой первый токен, не являющийся известной подкомандой, трактуется как псевдоним сервера: sss prod — это то же самое, что sss connect prod.

Глава 06
Графический интерфейс

В главном окне — складная боковая панель с 9 страницами и строка состояния (активные сеансы и туннели). Интерфейс доступен на 7 языках — английский, персидский, арабский, китайский, русский, испанский и французский — с настоящим RTL для персидского и арабского; тёмная/светлая тема переключается в Settings.

› Горячие клавиши

Ctrl+1..9 переключение страниц · Ctrl+N новый сервер · Ctrl+K новый сеанс терминала · Ctrl+Q выход.

Полная синхронизация GUI и CLI: оба интерфейса используют одну базу, один Keyring и одни настройки; сервер, созданный в GUI, мгновенно известен sss во всех терминалах — и наоборот.
Глава 07
Настоящий терминал (PTY)

Каждая вкладка терминала — настоящий PTY-сеанс поверх OpenSSH, а не текстовое поле. Всё, что возможно в настоящем терминале, возможно и здесь:

  • Цвета, стрелки, автодополнение по Tab, запуск vim, nano и htop работают корректно.
  • Ctrl+C и Ctrl+D прерывают и закрывают процессы точно как в системном терминале.
  • Копирование: выделите текст мышью (копируется автоматически) или используйте панель; вставка: средняя кнопка, панель или Ctrl+V внутри терминала.
  • Изменение размера: перетаскивание окна мгновенно сообщает программе на сервере (SIGWINCH) — редакторы и htop перерисовываются правильно.
  • Каждая вкладка показывает имя сервера и заголовок окна с сервера; для повторного подключения просто откройте новый сеанс того же сервера.
Приватность: содержимое терминала никогда не записывается в лог; в истории сохраняются только статус подключения и его длительность.
Глава 08
Работа с файлами через SFTP

На странице Files выберите сервер и нажмите Connect: левая панель — ваша локальная система, правая — сервер. Навигация: двойной клик по папкам, кнопка «вверх» или правка пути напрямую. Поддерживаются все повседневные операции:

  • Загрузка и скачивание перетаскиванием или кнопками.
  • Новая папка, переименование, удаление (с подтверждением, рекурсивно).
  • Смена прав в восьмеричном виде (например 0644) — без счёта в уме.
  • Правка текстовых файлов: файл открывается локально, после сохранения предлагается повторная загрузка.
  • «Отправить на сервер…»: переместите файл напрямую между двумя зарегистрированными серверами — без скачивания через вашу машину.
Если SFTP не работает, а терминал работает: возможно, на сервере отключена подсистема SFTP (Subsystem sftp в sshd_config) или ключ хоста ещё не принят — подключитесь один раз через терминал или нажмите Test.
Глава 09
Ключи, туннели и сохранённые команды

› SSH-ключи

Генерируйте ключи Ed25519 (рекомендуется), RSA или ECDSA в стандартном формате OpenSSH; необязательная парольная фраза ключа тоже сохраняется в Keyring. Регистрируйте существующие ключи (без копирования файла) или, по вашему явному выбору, копируйте их в хранилище приложения с правами 0600. Столбец отпечатка помогает проверке, столбец «связанные серверы» показывает, кто использует каждый ключ, а «Установить на сервер» собирает команду ssh-copy-id и выполняет её в сеансе терминала.

sss keys generate --name deploy --type ed25519 sss keys import --path ~/.ssh/id_ed25519 --name personal sss keys export-pub deploy

› Туннели портов

Три типа туннелей: Local (например 127.0.0.1:5432 → db-internal:5432 для доступа к внутренней базе), Remote (обратный — открыть порт локального сервиса на сервере) и Dynamic (прокси SOCKS5 вроде 127.0.0.1:1080). Туннели работают в независимом демоне — они не умирают при закрытии GUI или CLI, а их состояние видно в sss current.

sss tunnel db # start the tunnel named "db" sss tunnel stop db sss current # live sessions + running tunnels

› Сохранённые команды

Сохраняйте часто используемые команды для конкретного сервера или глобально (имя, команда, категория). Чувствительные команды с флагом «требует подтверждения» спрашивают перед выполнением. Запуск — со страницы Commands в GUI или через sss prod --exec "<command>" в терминале.

Глава 10
Модель безопасности

SSH Desk создан для хранения учётных данных боевых серверов и от начала до конца построен на одном принципе: секреты живут только в Secret Service. Ключевые меры контроля:

1 — Пароли только в GNOME Keyring

База данных хранит лишь ссылку без секрета (JSON); сам пароль никогда не попадает в SQLite (проверено автоматическими тестами).

2 — Безопасный askpass, не sshpass

OpenSSH запускается с SSH_ASKPASS_REQUIRE=force и безопасным помощником, который читает секрет «по ссылке» из Keyring; пароль не появляется в argv, окружении, логах или временных файлах.

3 — Ключи хоста всегда строгие

StrictHostKeyChecking=yes окончателен в конструкторе команд и отключить его нельзя; неизвестный хост → диалог отпечатка; изменённый ключ → предупреждение MITM и подсказка ssh-keygen -R.

4 — Устойчивость к инъекциям

Все вызовы subprocess используют массивы аргументов без shell=True; удалённые пути экранируются shlex.quote, а все входные данные проверяются Pydantic.

› Прочие меры

  • Права файлов: база и конфигурация 0600, папки данных 0700, приватные ключи 0600.
  • Логгер вычищает шаблоны password=, secret= и секреты, зарегистрированные во время работы.
  • Показ/копирование пароля требует ввода псевдонима сервера; буфер обмена очищается автоматически через 30 секунд.
  • Чувствительные операции — удаление сервера, рекурсивное удаление файлов, полное стирание данных (ввод PURGE) — всегда требуют подтверждения.
  • Никакой демон не работает от root; GUI и CLI никогда не требуют sudo.
  • Генерация ключей полностью внутрипроцессная; парольная фраза ключа не попадает в argv или временные файлы.
  • Экспорт/резервная копия по умолчанию без секретов; включение секретов — явный выбор с предупреждением.
Глава 11
Резервные копии, перенос и диагностика

› Резервное копирование и восстановление

sss backup backup.toml # no secrets by default sss restore backup.toml sss export full.toml --include-secrets # opt-in + warning sss import --file ~/.ssh/config # preview, then: --apply

Импорт из ~/.ssh/config выполняется с предпросмотром и обнаружением дублирующихся серверов; экспорт TOML предназначен для переноса настроек на другую машину и не содержит секретов, пока вы сами не попросите.

› Частые ошибки и решения

СимптомРешение

Полный сброс: sss uninstall-data — для стирания данных и секретов Keyring нужно ввести PURGE.
