Capítulo 01
Presentación de SSH Desk

SSH Desk es un producto real e instalable para gestionar todos tus servidores SSH en Ubuntu — no una demostración. Tres módulos — la interfaz gráfica, la línea de comandos y el núcleo compartido — trabajan exactamente sobre una base de datos y un almacén de secretos: registra un servidor en la GUI y conéctate desde cualquier terminal con sss prod en el mismo instante, incluso cuando la GUI no esté en ejecución.

El motor de conexión es el OpenSSH del propio sistema; el protocolo SSH no se vuelve a implementar, por lo que el comportamiento de conexión es idéntico al de Ubuntu. El terminal integrado es un PTY real: los colores, las flechas, Ctrl+C, vim y nano funcionan correctamente. Las contraseñas se guardan solo en GNOME Keyring y nunca llegan a la base de datos, los registros, los argumentos de comandos ni las variables de entorno.

GUI — interfaz de escritorio

PySide6 con temas oscuro/claro, 7 idiomas de interfaz con RTL completo para persa y árabe, terminal multipestaña y gestor de archivos.

CLI — línea de comandos

El comando sss funciona sin la GUI; el nombre del comando es configurable; incluye autocompletado bash/zsh.

Core — motor compartido

SQLite + SQLAlchemy con migraciones, el servicio Keyring, el constructor de comandos ssh y la política de Host Key.

Capítulo 02
Instalación y configuración

› Requisitos previos

# Ubuntu 22.04 / 24.04+ sudo apt update sudo apt install -y openssh-client gnome-keyring libsecret-1-0 \ python3 python3-venv python3-pip

› Opción A — instalación a nivel de usuario (recomendada, sin sudo)

git clone https://github.com/hmplus28/SSH-Desk.git cd SSH-Desk bash scripts/install.sh

El script comprueba Python y OpenSSH, crea un entorno virtual en ~/.local/share/ssh-desk/venv, instala el paquete con todas las dependencias y crea en ~/.local/bin los accesos ssh-desk (GUI), ssh-desk-cli, ssh-desk-askpass y sss; también instala el autocompletado de bash y el icono de la aplicación.

› Opción B — paquete DEB para todo el sistema

bash scripts/package_deb.sh sudo apt install ./dist/ssh-desk_1.0.0_amd64.deb

El DEB instala un conjunto autocontenido de PyInstaller bajo /opt/ssh-desk y registra la entrada de menú y el icono del sistema. La actualización se hace instalando el paquete más nuevo en su lugar; tus datos y secretos quedan intactos.

› Internet débil o interrumpido: espejos e instalación sin conexión

Si tu red es inestable o PyPI es difícil de alcanzar, no te preocupes: cada llamada a pip en los scripts de instalación prueba automáticamente una cadena de espejos — si un espejo no está accesible se salta sin intervención tuya y se prueba el siguiente. El orden por defecto es PyPI oficial → ArvanCloud (Irán) → TUNA → Aliyun → Tencent.

# force a specific working mirror bash scripts/install.sh --mirror-name ir # ArvanCloud (Iran) bash scripts/install.sh --mirror-name tuna # TUNA (China) # 1) download everything once (on any working network) bash scripts/download_wheels.sh --mirror-name ir # 2) install later with NO network at all bash scripts/install.sh --offline

En modo --offline, a pip no se le permite ninguna conexión de red e instala solo desde la carpeta vendor/wheels — así un corte de internet a mitad de la instalación ya no puede dejarla a medias. La misma cadena de espejos la usa scripts/build.sh, de modo que la construcción del DEB también queda protegida de los cortes.

Capítulo 03
Inicio rápido: tu primer servidor

Paso 1 — arranque: ejecuta ssh-desk para abrir la GUI; o quédate por completo en el terminal y usa sss add.

Paso 2 — añadir un servidor: en la página Servers pulsa «Add server». Introduce el nombre, el alias (único — con él te conectas), el host, el puerto, el usuario y la ruta por defecto. Si eliges autenticación por contraseña, el secreto se guarda enseguida en GNOME Keyring — no en la base de datos. Antes de guardar, el botón Test realiza una conexión real para que sepas que todo está correcto.

# the same thing from the terminal (interactive wizard) sss add sss add --alias prod --host 192.168.1.1 --port 22 --user root \ --auth password --path /var/www

Paso 3 — conexión: desde cualquier terminal escribe sss prod para abrir un shell interactivo en la ruta por defecto. En la GUI basta un doble clic sobre el servidor para abrir una pestaña de terminal real.

Primera conexión: se muestra la huella de la clave de host; compárala con tu administrador y acéptala una vez. Si la clave de host cambia más adelante, la conexión se rechaza al instante y se muestra cómo descartar un posible ataque MITM.
Capítulo 04
Conexión y gestión de rutas

Cada servidor puede tener una ruta por defecto y cualquier cantidad de rutas guardadas con nombre; por ejemplo, define una vez website → /var/www/html y nginx → /etc/nginx para el servidor de producción y salta siempre a esa carpeta con una sola palabra:

sss prod # shell at the server's default path sss prod nginx # shell at the saved path named "nginx" sss prod /var/www # shell at any absolute path sss prod --exec "uptime" # run one command, no shell sss prod --user ubuntu --port 2222 # per-run override (NOT saved) sss prod --dry-run # print the exact ssh command

Si la ruta solicitada no existe en el servidor, el mensaje de error es claro y comprensible — no una desconexión vaga. Las rutas se transfieren con entrecomillado seguro (shlex), de modo que los espacios o caracteres especiales en nombres de carpetas no dan problemas. Las opciones --user y --port se aplican solo a esa ejecución y nunca se guardan.

Capítulo 05
Referencia completa del CLI sss

El nombre de comando sss es un ejemplo; cámbialo con sss config cli-name cnc por el que quieras (cnc, sshgo, …) — el cambio se aplica en todo el sistema (un nuevo acceso en ~/.local/bin). Cualquier primer token que no sea un subcomando conocido se interpreta como alias de servidor, así que sss prod es lo mismo que sss connect prod.

Capítulo 06
La interfaz gráfica

La ventana principal tiene una barra lateral plegable con 9 páginas y una barra de estado (sesiones y túneles activos). La interfaz está disponible en 7 idiomas — inglés, persa, árabe, chino, ruso, español y francés — con disposición de derecha a izquierda real para persa y árabe; el tema oscuro/claro se cambia en Settings.

› Atajos de teclado

Ctrl+1..9 cambiar de página · Ctrl+N nuevo servidor · Ctrl+K nueva sesión de terminal · Ctrl+Q salir.

GUI y CLI siempre sincronizadas: ambas interfaces comparten una base de datos, un Keyring y una configuración; un servidor creado en la GUI lo reconoce sss al instante en todos los terminales — y viceversa.
Capítulo 07
El terminal real (PTY)

Cada pestaña de terminal es una sesión PTY real sobre OpenSSH — no una caja de texto. Todo lo posible en un terminal real es posible aquí:

  • Colores, flechas, autocompletado con Tab, y ejecutar vim, nano y htop funciona correctamente.
  • Ctrl+C y Ctrl+D interrumpen y cierran procesos exactamente como un terminal del sistema.
  • Copiar: selecciona texto con el ratón (copia automática) o usa la barra; pegar: clic central, la barra o Ctrl+V dentro del terminal.
  • Redimensionar: arrastrar la ventana informa al instante al programa del servidor (SIGWINCH) — los editores y htop se redibujan bien.
  • Cada pestaña muestra el nombre del servidor y el título de ventana del lado del servidor; para reconectar abre una nueva sesión del mismo servidor.
Privacidad: el contenido del terminal nunca se registra; en el historial solo se guardan el estado y la duración de la conexión.
Capítulo 08
Gestión de archivos con SFTP

En la página Files elige un servidor y pulsa Connect: el panel izquierdo es tu sistema local y el derecho el servidor. Navega con doble clic en carpetas, el botón «subir» o editando la ruta directamente. Todas las operaciones cotidianas están soportadas:

  • Subir y descargar arrastrando y soltando o con los botones.
  • Nueva carpeta, renombrar, eliminar (con confirmación, recursivo).
  • Cambiar permisos en forma octal (p. ej. 0644) — sin cálculos mentales.
  • Editar archivos de texto: el archivo se abre localmente y, tras guardar, se ofrece subirlo de nuevo.
  • «Enviar al servidor…»: mueve un archivo directamente entre dos servidores registrados — sin descargarlo pasando por tu máquina.
Si SFTP falla pero el terminal funciona: el servidor puede tener deshabilitado el subsistema SFTP (Subsystem sftp en sshd_config) o la clave de host aún no está aceptada — conéctate una vez por terminal o pulsa Test.
Capítulo 09
Claves, túneles y comandos guardados

› Claves SSH

Genera una clave Ed25519 (recomendada), RSA o ECDSA en el formato estándar de OpenSSH; la frase de contraseña opcional también se guarda en el Keyring. Registra claves existentes (sin copiar el archivo) o, por elección explícita tuya, cópialas al almacén de la aplicación con permisos 0600. La columna de huella ayuda a verificar, la de «servidores vinculados» muestra quién usa cada clave, y «Instalar en servidor» construye el comando ssh-copy-id y lo ejecuta en una sesión de terminal.

sss keys generate --name deploy --type ed25519 sss keys import --path ~/.ssh/id_ed25519 --name personal sss keys export-pub deploy

› Túneles de puertos

Tres tipos de túnel: Local (p. ej. 127.0.0.1:5432 → db-internal:5432 para alcanzar una base de datos interna), Remote (inverso — exponer en el servidor un puerto de un servicio local) y Dynamic (un proxy SOCKS5 como 127.0.0.1:1080). Los túneles corren en un demonio independiente — sobreviven al cierre de la GUI o el CLI y su estado se ve en sss current.

sss tunnel db # start the tunnel named "db" sss tunnel stop db sss current # live sessions + running tunnels

› Comandos guardados

Guarda comandos frecuentes por servidor o globalmente (nombre, comando, categoría). Los comandos sensibles con la marca «requiere confirmación» preguntan antes de ejecutarse. Ejecútalos desde la página Commands de la GUI o con sss prod --exec "<command>" en el terminal.

Capítulo 10
El modelo de seguridad

SSH Desk está diseñado para guardar las credenciales de servidores de producción y se construye de principio a fin sobre un principio: los secretos viven solo en el Secret Service. Los controles más importantes:

1 — Contraseñas solo en GNOME Keyring

La base de datos guarda solo una referencia sin secreto (JSON); la contraseña nunca llega a SQLite (verificado con pruebas automatizadas).

2 — askpass segura, no sshpass

OpenSSH se ejecuta con SSH_ASKPASS_REQUIRE=force y un ayudante seguro que lee el secreto «por referencia» del Keyring; la contraseña nunca aparece en argv, el entorno, los registros ni archivos temporales.

3 — Claves de host siempre estrictas

StrictHostKeyChecking=yes es definitivo en el constructor de comandos y no se puede desactivar; host desconocido → diálogo de huella; clave cambiada → aviso de MITM y guía de ssh-keygen -R.

4 — Resistente a inyecciones

Todas las llamadas a subprocess usan matrices de argumentos sin shell=True; las rutas remotas se entrecomillan con shlex.quote y toda entrada se valida con Pydantic.

› Otros controles

  • Permisos de archivos: base de datos y configuración 0600, carpetas de datos 0700, claves privadas 0600.
  • El registrador limpia los patrones password=, secret= y los secretos registrados en tiempo de ejecución.
  • Revelar/copiar una contraseña exige teclear el alias del servidor; el portapapeles se borra automáticamente tras 30 segundos.
  • Las operaciones sensibles — borrar un servidor, borrado recursivo de archivos, purga total de datos (teclear PURGE) — siempre piden confirmación.
  • Ningún demonio se ejecuta como root; la GUI y el CLI nunca necesitan sudo.
  • La generación de claves es totalmente dentro del proceso; la frase de la clave nunca llega a argv ni a archivos temporales.
  • La exportación/copia de seguridad no contiene secretos por defecto; incluirlos es opcional con aviso explícito.
Capítulo 11
Copias, transferencia y resolución de problemas

› Copia de seguridad y restauración

sss backup backup.toml # no secrets by default sss restore backup.toml sss export full.toml --include-secrets # opt-in + warning sss import --file ~/.ssh/config # preview, then: --apply

La importación desde ~/.ssh/config se hace con vista previa y detección de servidores duplicados; la exportación TOML sirve para llevar la configuración a otra máquina y no contiene secretos hasta que lo pidas explícitamente.
