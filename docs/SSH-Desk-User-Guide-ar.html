تعريف بـ SSH Desk

‏SSH Desk منتج حقيقي قابل للتثبيت لإدارة جميع خوادم SSH على أوبونتو — وليس عرضًا توضيحيًا. ثلاث وحدات — الواجهة الرسومية وسطر الأوامر والنواة المشتركة — تعمل على قاعدة بيانات واحدة ومخزن أسرار واحد بالضبط: سجّل خادمًا في الواجهة الرسومية واتصل به فورًا من أي طرفية بالأمر sss prod، حتى لو لم تكن الواجهة الرسومية تعمل أصلًا.

محرك الاتصال هو OpenSSH الخاص بالنظام؛ لم يُعَد تنفيذ بروتوكول SSH، لذا فإن سلوك الاتصال مطابق لأوبونتو تمامًا. الطرفية المدمجة هي PTY حقيقية: الألوان وأسهم الاتجاهات وCtrl+C وتشغيل vim وnano كلها تعمل بشكل صحيح. كلمات المرور تُخزَّن في GNOME Keyring فقط ولا تصل أبدًا إلى قاعدة البيانات أو السجلات أو معاملات الأوامر أو متغيرات البيئة.

GUI — الواجهة الرسومية

PySide6 بثيمات داكنة/فاتحة، و7 لغات للواجهة مع دعم RTL كامل للعربية والفارسية، وطرفية متعددة التبويبات ومدير ملفات.

CLI — سطر الأوامر

الأمر sss يعمل دون الواجهة الرسومية؛ اسم الأمر قابل للتخصيص؛ مع إكمال تلقائي لـ bash/zsh.

Core — النواة المشتركة

SQLite + SQLAlchemy مع الترحيلات، وخدمة Keyring، وباني أوامر ssh، وسياسة Host Key.

التثبيت والإعداد

› المتطلبات المسبقة

# Ubuntu 22.04 / 24.04+ sudo apt update sudo apt install -y openssh-client gnome-keyring libsecret-1-0 \ python3 python3-venv python3-pip

› الخيار أ — تثبيت على مستوى المستخدم (موصى به، دون sudo)

git clone https://github.com/hmplus28/SSH-Desk.git cd SSH-Desk bash scripts/install.sh

يفحص السكربت Python وOpenSSH، وينشئ بيئة افتراضية في ~/.local/share/ssh-desk/venv، ويثبت الحزمة بجميع تبعياتها، وينشئ الاختصارات ssh-desk (الواجهة الرسومية) وssh-desk-cli وssh-desk-askpass وsss في ~/.local/bin؛ كما يثبت الإكمال التلقائي لـ bash وأيقونة التطبيق.

› الخيار ب — حزمة DEB على مستوى النظام

bash scripts/package_deb.sh sudo apt install ./dist/ssh-desk_1.0.0_amd64.deb

تثبت حزمة DEB حِزمة PyInstaller مستقلة تحت /opt/ssh-desk وتسجّل مدخلة القائمة وأيقونة النظام. الترقية تتم بتثبيت الحزمة الأحدث مكانها؛ تبقى بياناتك وأسرارك كما هي دون مساس.

› إنترنت ضعيف أو منقطع: الميرورات والتثبيت دون اتصال

إذا كانت شبكتك غير مستقرة أو يصعب الوصول إلى PyPI، فلا تقلق: كل استدعاء pip في سكربتات التثبيت يجرب تلقائيًا سلسلة من الميرورات — إذا تعذر الوصول إلى ميرور يُتجاهل دون أي تدخل منك ويُجرَّب التالي. الترتيب الافتراضي: PyPI الرسمي ← ArvanCloud (إيران) ← TUNA ← Aliyun ← Tencent.

# force a specific working mirror bash scripts/install.sh --mirror-name ir # ArvanCloud (Iran) bash scripts/install.sh --mirror-name tuna # TUNA (China) # 1) download everything once (on any working network) bash scripts/download_wheels.sh --mirror-name ir # 2) install later with NO network at all bash scripts/install.sh --offline

في وضع --offline لا يُسمح لـ pip بأي اتصال شبكي ويثبت فقط من مجلد vendor/wheels — لذا لا يمكن لانقطاع الإنترنت في منتصف التثبيت أن يترك التثبيت ناقصًا بعد الآن. تُستخدم سلسلة الميرورات نفسها في scripts/build.sh، فتكون عملية بناء DEB محمية من الانقطاعات أيضًا.

الفصل ٠٣
البداية السريعة: أول خادم

الخطوة ١ — التشغيل: نفّذ ssh-desk لفتح الواجهة الرسومية؛ أو ابقَ في الطرفية تمامًا واستخدم sss add.

الخطوة ٢ — إضافة خادم: في صفحة Servers اضغط «Add server». أدخل الاسم والاسم المستعار (فريد — به تتصل) والمضيف والمنفذ واسم المستخدم والمسار الافتراضي. إذا اخترت المصادقة بكلمة مرور، يُخزَّن السر فورًا في GNOME Keyring — لا في قاعدة البيانات. قبل الحفظ يجري زر Test اتصالًا حقيقيًا لتتأكد أن كل شيء صحيح.

# the same thing from the terminal (interactive wizard) sss add sss add --alias prod --host 192.168.1.1 --port 22 --user root \ --auth password --path /var/www

الخطوة ٣ — الاتصال: اكتب من أي طرفية sss prod لفتح صَدَفة تفاعلية على المسار الافتراضي. في الواجهة الرسومية يكفي النقر المزدوج على الخادم لفتح تبويب طرفية حقيقي.

أول اتصال: تُعرض بصمة مفتاح المضيف؛ قارنها مع مدير الخادم واقبلها مرة واحدة. إذا تغيّر مفتاح المضيف لاحقًا، يُرفض الاتصال فورًا وتُعرض إرشادات للتحقق من احتمال هجوم MITM.
الفصل ٠٤
الاتصال وإدارة المسارات

يمكن لكل خادم أن يكون له مسار افتراضي وأي عدد من المسارات المحفوظة المسماة؛ مثلًا عرّف مرة واحدة website → /var/www/html وnginx → /etc/nginx لخادم الإنتاج وانتقل دائمًا إلى ذلك المجلد بكلمة واحدة:

sss prod # shell at the server's default path sss prod nginx # shell at the saved path named "nginx" sss prod /var/www # shell at any absolute path sss prod --exec "uptime" # run one command, no shell sss prod --user ubuntu --port 2222 # per-run override (NOT saved) sss prod --dry-run # print the exact ssh command

إذا لم يكن المسار المطلوب موجودًا على الخادم، فرسالة الخطأ واضحة ومفهومة — وليست انقطاعًا غامضًا. تُنقل المسارات بعلامات اقتباس آمنة (shlex) فلا تسبب المسافات أو الرموز الخاصة في أسماء المجلدات مشكلة. يُطبَّق الخياران --user و--port على ذلك التشغيل فقط ولا يُحفظان أبدًا.

الطرفية الحقيقية (PTY)

كل تبويب طرفية هو جلسة PTY حقيقية عبر OpenSSH — وليس مربع نص. كل ما هو ممكن في طرفية حقيقية ممكن هنا:

  • الألوان وأسهم الاتجاهات وإكمال Tab وتشغيل vim وnano وhtop تعمل بشكل صحيح.
  • Ctrl+C وCtrl+D يقطعان العمليات ويغلقانهما تمامًا مثل طرفية النظام.
  • النسخ: حدد النص بالفأرة (نسخ تلقائي) أو استخدم شريط الأدوات؛ اللصق: النقر الأوسط أو شريط الأدوات أو Ctrl+V داخل الطرفية.
  • تغيير الحجم: سحب النافذة يبلّغ البرنامج على الخادم فورًا (SIGWINCH) — يعيد المحررون وhtop الرسم بشكل صحيح.
  • يعرض كل تبويب اسم الخادم وعنوان النافذة من جهة الخادم؛ لإعادة الاتصال افتح جلسة جديدة للخادم نفسه.
الخصوصية: لا يُسجَّل محتوى الطرفية أبدًا؛ يُسجل في السجل حالة الاتصال ومدته فقط.
الفصل ٠٨
إدارة الملفات عبر SFTP

في صفحة Files اختر خادمًا واضغط Connect: الجزء الأيسر نظامك المحلي والأيمن هو الخادم. تنقّل بالنقر المزدوج على المجلدات أو زر «للأعلى» أو بتحرير المسار مباشرة. كل العمليات اليومية مدعومة:

  • الرفع والتنزيل بالسحب والإفلات أو عبر الأزرار.
  • مجلد جديد، إعادة تسمية، حذف (مع تأكيد، وبشكل متكرر).
  • تغيير الصلاحيات بصيغة ثمانية (مثل 0644) — دون حساب ذهني.
  • تحرير الملفات النصية: يفتح الملف محليًا وبعد الحفق يُقترح رفعه من جديد.
  • «إرسال إلى خادم...»: انقل ملفًا مباشرة بين خادمين مسجلين — دون تنزيله عبر جهازك.
إذا فشل SFTP بينما تعمل الطرفية: قد يكون الخادم قد عطّل نظام SFTP الفرعي (Subsystem sftp في sshd_config) أو لم يُقبل مفتاح المضيف بعد — اتصل مرة عبر الطرفية أو اضغط Test.
الفصل ٠٩
المفاتيح والأنفاق والأوامر المحفوظة

› مفاتيح SSH

وّلد مفتاح Ed25519 (موصى به) أو RSA أو ECDSA بصيغة OpenSSH القياسية؛ تُخزَّن عبارة مرور المفتاح الاختيارية في Keyring أيضًا. سجّل المفاتيح الموجودة (دون نسخ الملف) أو انسخها بقرارك الصريح إلى مخزن التطبيق بصلاحية 0600. يساعد عمود البصمة في التحقق، وعمود «الخوادم المرتبطة» يُظهر مستخدمي كل مفتاح، و«التثبيت على الخادم» يبني أمر ssh-copy-id وينفذه في جلسة طرفية.

sss keys generate --name deploy --type ed25519 sss keys import --path ~/.ssh/id_ed25519 --name personal sss keys export-pub deploy

› أنفاق المنافذ

ثلاثة أنواع من الأنفاق: Local (مثل 127.0.0.1:5432 → db-internal:5432 للوصول إلى قاعدة بيانات داخلية)، وRemote (عكسي — عرض منفذ خدمة محلية على الخادم)، وDynamic (بروكسي SOCKS5 مثل 127.0.0.1:1080). تعمل الأنفاق في ديمون مستقل — لا تموت بإغلاق الواجهة أو سطر الأوامر وتظهر حالتها في sss current.

sss tunnel db # start the tunnel named "db" sss tunnel stop db sss current # live sessions + running tunnels

› الأوامر المحفوظة

احفظ الأوامر المتكررة لكل خادم أو عالميًا (الاسم، الأمر، الفئة). تسأل الأوامر الحساسة بعلامة «يتطلب تأكيدًا» قبل التنفيذ. التنفيذ من صفحة Commands في الواجهة أو عبر sss prod --exec "<command>" في الطرفية.

الفصل ١٠
نموذج الأمان

صُمم SSH Desk لحفظ بيانات اعتماد خوادم الإنتاج، ومبني على مبدأ واحد من البداية إلى النهاية: الأسرار تبقى في Secret Service فقط. أهم الضوابط:

١ — كلمات المرور في GNOME Keyring فقط

تخزن قاعدة البيانات مرجعًا بلا سر فقط (JSON)؛ لا تصل كلمة المرور نفسها إلى SQLite أبدًا (مُتحقق منه باختبارات آلية).

٢ — askpass آمنة، لا sshpass

يعمل OpenSSH مع SSH_ASKPASS_REQUIRE=force ومساعد آمن يقرأ السر «بالمرجع» من Keyring؛ لا تظهر كلمة المرور في argv أو البيئة أو السجلات أو الملفات المؤقتة.

٣ — مفاتيح المضيف صارمة دائمًا

StrictHostKeyChecking=yes نهائي في باني الأوامر ولا يمكن تعطيله؛ مضيف مجهول ← حوار البصمة؛ مفتاح متغير ← تحذير MITM وإرشادات ssh-keygen -R.

٤ — مقاوم للحقن

كل استدعاءات subprocess تستخدم مصفوفات وسائط دون shell=True؛ تُقتبس المسارات البعيدة بـ shlex.quote ويُتحقق من كل المدخلات عبر Pydantic.

› ضوابط أخرى

  • صلاحيات الملفات: قاعدة البيانات والإعدادات 0600، مجلدات البيانات 0700، المفاتيح الخاصة 0600.
  • يمسح المسجل أنماط password= وsecret= والأسرار المسجلة وقت التشغيل.
  • عرض/نسخ كلمة المرور يتطلب كتابة الاسم المستعار؛ ويُمسح الحافظة تلقائيًا بعد 30 ثانية.
  • العمليات الحساسة — حذف خادم، حذف ملفات متكرر، مسح كامل للبيانات (كتابة PURGE) — تطلب التأكيد دائمًا.
  • لا يعمل أي ديمون بصلاحية root؛ لا تحتاج الواجهة الرسومية أو سطر الأوامر sudo أبدًا.
  • توليد المفاتيح داخل العملية بالكامل؛ لا تصل عبارة مرور المفتاح إلى argv أو ملفات مؤقتة.
  • التصدير/النسخ الاحتياطي بلا أسرار افتراضيًا؛ تضمين الأسرار اختياري مع تحذير صريح.

النسخ الاحتياطي والنقل واستكشاف الأخطاء

› النسخ الاحتياطي والاستعادة

sss backup backup.toml # no secrets by default sss restore backup.toml sss export full.toml --include-secrets # opt-in + warning sss import --file ~/.ssh/config # preview, then: --apply

يتم الاستيراد من ~/.ssh/config مع معاينة وكشف الخوادم المكررة؛ تصدير TOML لنقل الإعدادات إلى جهاز آخر ولا يحتوي أسرارًا حتى تطلب ذلك صراحةً.
