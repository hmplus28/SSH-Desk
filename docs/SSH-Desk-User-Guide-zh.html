第 01 章
SSH Desk 简介

SSH Desk 是一款真实可安装的产品，用于管理 Ubuntu 上的所有 SSH 服务器——不是演示原型。三大模块——桌面图形界面、命令行与共享内核——完全运行在同一数据库和同一机密存储之上：在图形界面里登记一台服务器，立刻就能在任意终端用 sss prod 连接，即使图形界面根本没有运行。

连接引擎是系统自带的 OpenSSH；我们不重新实现 SSH 协议，因此连接行为与 Ubuntu 原生完全一致。内置终端是真实 PTY：颜色、方向键、Ctrl+C、vim 与 nano 都能正常工作。密码只存储在 GNOME Keyring 中，绝不会进入数据库、日志、命令行参数或环境变量。

GUI — 桌面界面

PySide6，深色/浅色主题，7 种界面语言（波斯语与阿拉伯语完整 RTL），多标签终端与文件管理器。

CLI — 命令行

sss 命令无需图形界面即可使用；命令名可配置；附带 bash/zsh 补全。

Core — 共享内核

SQLite + SQLAlchemy 含迁移，密钥环服务，ssh 命令构建器与 Host Key 策略。

第 02 章
安装与配置

› 前置条件

# Ubuntu 22.04 / 24.04+ sudo apt update sudo apt install -y openssh-client gnome-keyring libsecret-1-0 \ python3 python3-venv python3-pip

› 方案 A —— 用户级安装（推荐，无需 sudo）

git clone https://github.com/hmplus28/SSH-Desk.git cd SSH-Desk bash scripts/install.sh

脚本会检查 Python 与 OpenSSH，在 ~/.local/share/ssh-desk/venv 创建虚拟环境，连同全部依赖安装软件包，并在 ~/.local/bin 创建 ssh-desk（图形界面）、ssh-desk-cli、ssh-desk-askpass 与 sss 快捷方式；同时安装 bash 补全和应用图标。

› 方案 B —— 系统级 DEB 软件包

bash scripts/package_deb.sh sudo apt install ./dist/ssh-desk_1.0.0_amd64.deb

DEB 包会将自包含的 PyInstaller 套装安装到 /opt/ssh-desk，并注册菜单项与系统图标。升级只需原地安装新包；你的数据与机密保持不动。

› 网络不稳定或中断：镜像与离线安装

如果你的网络不稳定或难以访问 PyPI，无需担心：安装脚本中的每次 pip 调用都会自动尝试一条镜像链——某个镜像不可达时会被自动跳过，无需任何人工干预，接着尝试下一个。默认顺序为：PyPI 官方源 → ArvanCloud（伊朗）→ TUNA → Aliyun → Tencent。

# force a specific working mirror bash scripts/install.sh --mirror-name ir # ArvanCloud (Iran) bash scripts/install.sh --mirror-name tuna # TUNA (China) # 1) download everything once (on any working network) bash scripts/download_wheels.sh --mirror-name ir # 2) install later with NO network at all bash scripts/install.sh --offline

在 --offline 模式下，pip 不允许任何网络连接，只从 vendor/wheels 目录安装——因此安装中途断网也不会再留下半成品安装。scripts/build.sh 使用同一条镜像链，DEB 构建同样不受断网影响。

› 重要文件在哪里？

位置路径
应用数据库~/.local/share/ssh-desk/ssh-desk.db
设置~/.config/ssh-desk/config.toml
应用 known_hosts~/.local/share/ssh-desk/known_hosts
生成的密钥~/.local/share/ssh-desk/keys/
日志~/.local/share/ssh-desk/logs/
密码与机密GNOME Keyring (Secret Service)
卸载：bash scripts/uninstall.sh 在删除数据与机密之前会明确征得你的同意；未经确认不会删除任何东西。
第 03 章
快速上手：第一台服务器

第 1 步 —— 启动：运行 ssh-desk 打开图形界面；或者完全留在终端里使用 sss add。

第 2 步 —— 添加服务器：在 Servers 页面点击“添加服务器”。填写名称、别名（唯一——连接时使用）、主机、端口、用户名与默认路径。如果选择密码认证，机密会立即存入 GNOME Keyring——而不是数据库。保存前，Test 按钮会发起一次真实连接，确保一切正确。

# the same thing from the terminal (interactive wizard) sss add sss add --alias prod --host 192.168.1.1 --port 22 --user root \ --auth password --path /var/www

第 3 步 —— 连接：在任意终端输入 sss prod，即可在默认路径打开交互式 Shell。在图形界面中，双击服务器即可打开真实终端标签页。

首次连接：会显示主机密钥指纹；请与服务器管理员核对后接受一次。若日后主机密钥发生变更，连接会立即被拒绝，并显示排查中间人（MITM）攻击风险的指引。
第 04 章
连接与路径管理

每台服务器都可以有默认路径以及任意数量的命名保存路径；例如为生产服务器一次性定义 website → /var/www/html 与 nginx → /etc/nginx，之后总能用一个词跳转到那个目录：

sss prod # shell at the server's default path sss prod nginx # shell at the saved path named "nginx" sss prod /var/www # shell at any absolute path sss prod --exec "uptime" # run one command, no shell sss prod --user ubuntu --port 2222 # per-run override (NOT saved) sss prod --dry-run # print the exact ssh command

如果请求的路径在服务器上不存在，错误信息清晰易懂——而不是含糊的断连。路径使用安全引号（shlex）传输，文件夹名中的空格或特殊字符不会造成麻烦。--user 与 --port 选项只对当次运行生效，绝不保存。

› 命令行退出码

退出码含义
0操作成功
1运行时错误（连接、网络、密钥环等）
2输入无效或命令用法错误
130被 Ctrl+C 中断

这些退出码让 sss 在脚本和自动化中表现可靠；例如可以在 CI 或 cron 中检查连接是否成功。

第 05 章
sss 命令行完整参考

sss 只是示例名；用 sss config cli-name cnc 可以改成任何你喜欢的名字（cnc、sshgo 等）——更改在系统级生效（在 ~/.local/bin 创建新快捷方式）。第一个词若不是已知子命令，就会被解释为服务器别名，因此 sss prod 等价于 sss connect prod。

› 服务器

命令作用
sss list服务器表格；可用 --group --favorites --search 过滤
sss add交互式添加；所有字段也可直接以选项传入
sss info prod完整详情；--show-secret 需输入别名确认
sss edit prod编辑字段；--set-password 保存新密码
sss delete prod确认后删除；同时清除密钥环中的机密
sss search 关键词搜索名称、别名、主机、用户与描述

› 监控与配置

命令作用
sss history连接历史，可按服务器/条数/状态过滤
sss current活动 SSH 会话与运行中的隧道
sss config list所有设置与文件位置
sss config set KEY VALUE修改设置
sss config cli-name cnc系统级重命名命令
sss config completions安装 bash/zsh 补全

› 密钥、隧道与配置迁移

命令作用
sss keys generate以 OpenSSH 格式生成 Ed25519/RSA/ECDSA
sss keys import登记现有密钥（--copy 以 0600 权限复制进应用存储）
sss keys export-pub导出公钥
sss tunnel start|stop以独立守护进程运行隧道，脱离终端
sss import --file ~/.ssh/config导入 ssh config，带预览与重复检测
sss export FILE.toml备份；仅加 --include-secrets 才含机密
sss restore FILE.toml恢复备份
sss install-cli重建终端快捷方式
补全：bash 补全会自动安装（子命令 + 服务器别名）。zsh 请执行 sss config completions --shell zsh --install，再把 completions 路径加入 ~/.zshrc。
第 06 章
桌面图形界面

主窗口带有可折叠侧边栏（9 个页面）与状态栏（活动会话与隧道）。界面提供 7 种语言——英语、波斯语、阿拉伯语、中文、俄语、西班牙语与法语——波斯语与阿拉伯语为真实的从右向左布局；深色/浅色主题在 Settings 中切换。

添加/编辑服务器四个标签页：常规、身份验证、连接与路径、高级（跳板机与 ssh 选项）

› 键盘快捷键

图形界面与命令行始终同步：两个界面共享同一数据库、同一密钥环与同一份设置；图形界面创建的服务器，所有终端里的 sss 立即可用——反之亦然。
第 07 章
真实终端（PTY）

每个终端标签页都是基于 OpenSSH 的真实 PTY 会话——不是文本框。真实终端能做到的，这里都能做到：

  • 颜色、方向键、Tab 补全，以及运行 vim、nano、htop 都正常。
  • Ctrl+C 与 Ctrl+D 与系统终端完全一致地中断并关闭进程。
  • 复制：用鼠标选中文本（自动复制）或使用工具栏；粘贴：中键、工具栏或终端内 Ctrl+V。
  • 调整大小：拖动窗口会立即通知服务器端程序（SIGWINCH）——编辑器与 htop 能正确重绘。
  • 每个标签页显示服务器名与服务器端窗口标题；要重连，为同一台服务器再开一个会话即可。
隐私：终端内容永远不会被记录；历史中只保存连接状态与时长。
第 08 章
SFTP 文件管理

在 Files 页面选择服务器并点击 Connect：左栏是你的本地系统，右栏是服务器。双击文件夹、“向上”按钮或直接编辑路径即可导航。日常操作全部支持：

  • 上传与下载：拖放或按钮均可。
  • 新建文件夹、重命名、删除（需确认，支持递归）。
  • 修改权限：八进制形式（如 0644）——无需心算。
  • 编辑文本文件：文件在本地打开编辑，保存后会提示重新上传。
  • “发送到服务器…”：在两台已登记服务器之间直接传文件——无需经你的机器中转下载。
如果 SFTP 失败但终端正常：服务器可能禁用了 SFTP 子系统（sshd_config 中的 Subsystem sftp），或主机密钥尚未被接受——先用终端连接一次或点击 Test。
第 09 章
密钥、隧道与已保存命令

› SSH 密钥

以标准 OpenSSH 格式生成 Ed25519（推荐）、RSA 或 ECDSA 密钥；密钥的可选密码短语同样存入密钥环。可以“登记”现有密钥（不复制文件），或在你的明确选择下以 0600 权限复制进应用存储。指纹列用于核对，“关联服务器”列显示每个密钥的使用者；“安装到服务器”会生成 ssh-copy-id 命令并在终端会话中执行。

sss keys generate --name deploy --type ed25519 sss keys import --path ~/.ssh/id_ed25519 --name personal sss keys export-pub deploy

› 端口隧道

三种隧道类型：Local（如 127.0.0.1:5432 → db-internal:5432，访问内网数据库）、Remote（反向——在服务器上开放本地服务端口）与 Dynamic（SOCKS5 代理，如 127.0.0.1:1080）。隧道运行在独立守护进程中——关闭图形界面或命令行也不会中断，状态可在 sss current 查看。

sss tunnel db # start the tunnel named "db" sss tunnel stop db sss current # live sessions + running tunnels

› 已保存命令

可为每台服务器或全局保存常用命令（名称、命令、分类）。带“需要确认”标记的敏感命令在运行前会询问。可在图形界面 Commands 页执行，或在终端用 sss prod --exec "<command>"。

第 10 章
安全模型

SSH Desk 的设计目标是保存生产服务器的凭据，从始至终坚持一条原则：机密只存在于 Secret Service。最重要的控制措施：

1 — 密码只存于 GNOME Keyring

数据库只保存无机密的引用（JSON）；密码本身永远不会进入 SQLite（已由自动化测试验证）。

2 — 安全 askpass，而非 sshpass

OpenSSH 以 SSH_ASKPASS_REQUIRE=force 和安全助手运行，助手“按引用”从密钥环读取机密；密码绝不出现在 argv、环境变量、日志或临时文件中。

3 — 主机密钥始终严格

StrictHostKeyChecking=yes 在命令构建器中是最终值，无法关闭；未知主机 → 指纹对话框；密钥变更 → MITM 警告与 ssh-keygen -R 指引。

4 — 抗注入

所有 subprocess 调用都使用参数数组而非 shell=True；远程路径用 shlex.quote 加引号，所有输入经 Pydantic 校验。

› 其他控制措施

  • 文件权限：数据库与配置 0600，数据目录 0700，私钥 0600。
  • 日志器会清洗 password=、secret= 模式以及运行时登记的机密。
  • 查看/复制密码需要输入服务器别名；剪贴板 30 秒后自动清空。
  • 敏感操作——删除服务器、递归删除文件、完全清除数据（输入 PURGE）——总是需要确认。
  • 没有任何守护进程以 root 运行；图形界面与命令行从不需要 sudo。
  • 密钥生成完全在进程内完成；密钥密码短语绝不进入 argv 或临时文件。
  • 导出/备份默认不含机密；包含机密是显式选择并伴随警告。
第 11 章
备份、迁移与故障排除

› 备份与恢复

sss backup backup.toml # no secrets by default sss restore backup.toml sss export full.toml --include-secrets # opt-in + warning sss import --file ~/.ssh/config # preview, then: --apply

从 ~/.ssh/config 导入时提供预览与重复服务器检测；TOML 导出用于把设置迁移到另一台机器，在你明确要求之前不含任何机密。

› 常见错误与解决方法

现象解决办法
sss: command not found把 ~/.local/bin 加入 PATH，或执行 sss install-cli
“Secret Service is not available”sudo apt install gnome-keyring libsecret-1-0，然后注销并登录一次
密钥环已锁定解锁一次；应用在可能时也会交互式询问
Host key changed核实之后才可继续：ssh-keygen -R "[host]:port"，然后重新接受
Permission denied密码：sss edit prod --set-password · 密钥：sss keys list
图形界面打不开ssh-desk 2>&1 | tail -20；安装 Qt 库；Wayland：QT_QPA_PLATFORM=xcb
隧道端口被占用ss -tlnp | grep <port>，然后 sss tunnel stop
完全重置：sss uninstall-data —— 必须输入 PURGE 才会清除数据与密钥环机密。
安全连接，触手可及。
