SSH Desk — реальный, устанавливаемый продукт (не прототип) для управления всеми вашими SSH-серверами: пароли хранятся **только** в GNOME Keyring (Secret Service), SSH-движком является системный **OpenSSH**, а встроенный терминал — это **настоящий PTY** (vim/nano, цвета, Ctrl+C, изменение размера — всё действительно работает).

- 🖥️ **Графический интерфейс** (PySide6): тёмная/светлая темы, персидский/английский (полный RTL), вкладки реального терминала, SFTP-менеджер файлов, туннели, ключи, история
- ⌨️ **CLI** (Typer): работает **без** GUI; имя команды настраивается (`sss`, `cnc`, `sshgo`, …); автодополнение bash/zsh, включая алиасы серверов
- 🔐 **Безопасность прежде всего**: строгая проверка host-ключей с диалогом отпечатка; секреты никогда не попадают в БД/логи/argv; без `sshpass` и без `StrictHostKeyChecking=no`
- 🌐 **Устойчивость к перебоям сети**: цепочка зеркал PyPI (официальное → ArvanCloud (Иран) → TUNA → Aliyun → Tencent) и полностью офлайн-установка через `install.sh --offline`

📄 **[Полное руководство пользователя (PDF, на фарси)](docs/SSH-Desk-User-Guide-fa.pdf)** — 14 страниц с иллюстрациями: офлайн-установка, полный справочник CLI, терминал, SFTP, туннели и модель безопасности.

## Быстрый старт

```bash
git clone https://github.com/hmplus28/SSH-Desk.git
cd SSH-Desk
bash scripts/install.sh
```

Затем:

```bash
ssh-desk          # графический интерфейс
sss add           # добавить первый сервер
sss prod          # подключение (интерактивный шелл в вашем терминале)
```

DEB-пакет и ручная установка: [docs/INSTALLATION.md](docs/INSTALLATION.md).
При слабом/отсутствующем интернете: `bash scripts/download_wheels.sh --mirror-name ir`, затем `bash scripts/install.sh --offline`.

## CLI за 30 секунд

```bash
sss                      # сводка + подсказки
sss list                 # таблица серверов
sss add                  # интерактивный мастер (или --alias/--host/...)
sss info prod            # полные сведения
sss test prod            # проверка подключения
sss prod                 # интерактивный шелл в пути по умолчанию
sss prod nginx           # подключение к сохранённому пути
sss prod /etc/nginx      # подключение к абсолютному пути
sss prod --exec "uptime" # выполнить команду (ничего не сохраняется)
sss prod --user ubuntu --port 2222   # переопределение на один запуск
sss history              # история подключений
sss current              # активные сессии + запущенные туннели
sss tunnel db            # запустить именованный туннель (живёт отдельно)
sss config cli-name cnc  # переименовать команду на уровне ОС
sss --help               # полный справочник
```

## Возможности

| Область | Что реально работает |
| --- | --- |
| Серверы | CRUD, уникальные алиасы, группы, теги, избранное, дублирование, поиск/сортировка/фильтры |
| Аутентификация | Пароль (Keyring), приватный ключ (+пароль в Keyring), SSH agent, интерактивно |
| Пути | Путь по умолчанию + именованные сохранённые пути (`sss prod nginx`), безопасное экранирование |
| Терминал | Настоящий PTY (OpenSSH), вкладки, цвета, vim/nano, изменение размера, копирование/вставка |
| Файлы | Двухпанельный SFTP-менеджер: загрузка/скачивание/mkdir/переименование/chmod/редактирование/удаление, передача сервер↔сервер |
| Ключи | Генерация Ed25519/RSA/ECDSA в формате OpenSSH, импорт, отпечаток, экспорт публичного ключа, подсказка `ssh-copy-id` |
| Туннели | Local / Remote / Dynamic SOCKS, запуск/остановка, отдельный демон, отслеживание состояния |
| Jump-хосты | `ProxyCommand` через `ssh -W` с любым зарегистрированным сервером (вложенные цепочки) |
| Команды | Сохранённые команды на сервер или глобально, подтверждение опасных |
| История | Подключения/отключения, длительность, статус, ошибки (без содержимого терминала и паролей) |
| Импорт/экспорт | Импорт `~/.ssh/config` с предпросмотром и дедупликацией, резервная копия/восстановление TOML (секреты по желанию) |

## Модель безопасности (кратко)

1. Пароли/парольные фразы живут **только** в Secret Service (GNOME Keyring); в БД хранится несекретная ссылка.
2. OpenSSH получает секреты через защищённый **askpass-хелпер** — никогда через argv, окружение или sshpass.
3. Проверка host-ключей обязательна (`StrictHostKeyChecking=yes`): неизвестный → диалог отпечатка; изменённый → жёсткое предупреждение.
4. Файлы БД/конфигурации с правами `0600`/`0700`; логи очищаются от секретов; никаких root-демонов.

Подробности: [docs/SECURITY.md](docs/SECURITY.md).
